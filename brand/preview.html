OnlyRead · Logo 方向评审

4 个 Logo 候选方向对比

这是 OnlyRead（跨 Windows / macOS / Ubuntu 的通用文件阅读器）的标志候选方向草案。 每个方向都出自同一套视觉语言：闭合形状用 1.8 描边，实心点用 currentColor 填充且不描边； 结构上只靠剪影 + 少量笔画成立，因为同一枚图标既要出现在 18px 标题栏、34px 欢迎页，还必须缩到 16px 仍可辨认。

16px 可辨认

缩到 16px 后仍能一眼读出「这是个阅读 / 文件类工具」，笔画不糊成一团、细节不丢失。这是本次评审的核心门槛。

与主色协调

只使用 currentColor，需同时适配浅色主题文字色与深色主题文字色，并能在 #2f7efc 渐变底上反白成立。

不与通用书本撞车

避免落进「折角文档 / 打开的书」这套已经被用滥的通用图标语汇；若必须使用，要能说明差异化在哪里。

技术规格：viewBox="0 0 24 24"，无写死宽高，可任意缩放；stroke-width="1.8"， stroke-linecap="round"，stroke-linejoin="round"；所有坐标落在 1.5 ~ 22.5 之内。 下面每个内联 SVG 的几何与 brand/logos/*.svg 文件逐字一致，不存在两套几何。

横向对比

以「16px 可辨认度」为一票否决项来读这张表：任何在 16px 下失效的方向，无论语义多好，都不能作为标题栏图标。

概念 语义强弱 16px 可辨认度 与通用图标撞车风险 备注
A · 双栏书 中
读出「书 / 对开页」，但读不出「文件树、可拖拽分栏」这些真正差异化的交互。		 高
最稳的一版。只有 4 条笔画，两条中缝竖线到 16px 仍有 6px 间距，纯剪影即可成立。		 中
「打开的书」是阅读器用滥的母题，但对称竖直折角的形式比常见的 V 形翻页稍少见。		 四个方向里几何风险最低。代价是它讲的是「阅读」，不是「OnlyRead 特有的左右分栏」。
B · 文件树 + 内容面板 强
唯一直接映射真实界面的方向，左边文件树、右边内容底部只有一个选择：B 或 D2。		 低
16px 下左侧方块仅 3.3px 宽，里面 3 根 1.5 单位短划各约 1px 宽且间距不足，会糊成一根竖条；右边 2 根文字线同理。		 低
不撞「书本 / 折角文档」这套主流语汇，也不像通用的「应用窗口 / 分栏」图标。		 方向本身最有产品味，但按当前几何无法直接当 16px 标题栏图标用。若要保留，得做「小尺寸简化版」：16px 时丢弃树里的 3 根短划，只留两个空方块。
C · 实体页 + 元数据镜像 强
唯一解释品牌名的方向：内容之上还有一层关于内容的层，正好对应「Meta」。		 中偏低
1.5 单位错位在 16px 下是 1px，层次还能看出，但虚线（1.47px 划 / 1.2px 隙）在低 DPI 屏上容易被抗锯齿抹成一截截浅灰线。		 中
双页叠影的形式不常见；但缩到 16px 后容易被误读成「复制 / 多窗口」，而不是「阅读」。		 最有个性、也最需要实测的一版。建议先在 100% 缩放的真实 Windows 标题栏里验证虚线是否还在，再决定是否采纳。
D / D2 · 折角页 + 文字线 / + 书签点 弱
只说明「这是个文档」，不含产品差异；D2 的书签点补上「收藏 / 进度」一维，但仍是通用语义。		 高
轮廓闭合、单一边界，16px 下完全清晰；D2 的书签点在 16px 下约 2.3×3px，是本方向唯一可能被抹掉的部分。		 高
折角文档是全球最通用的图标母题之一，几乎无法形成品牌识别，也与系统「文件 / 文档」图标正面冲突。		 作为基准对照很有价值：它定义了「可辨认但不独特」的下限。D2 比 D 好，因为书签点提供了第二个信息维度。

已实测（1x 渲染，见 brand/mark-a-check.png）：16px 一档里 只有 A 成立——B 糊成一个墨点、C 几乎不可见、D 也几乎不可读；A 在 stroke 2.4 时最清楚。 因此主标记已定为 A（双栏书），替换方案见 brand/ReaderMark-替换补丁.md。
注意：A 的 stroke 1.8 在 18px 下偏细、在 34px 下偏粗，已在补丁里改为按 size 选描边 （16px→2.4、18–24px→2.0、34px 及以上→1.8）。
仍未验证：150% / 200% 缩放下的真实任务栏与标题栏观感、以及实际打包后的效果。
